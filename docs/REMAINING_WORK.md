## 2. 밸런스 (오토플레이어 기준 수치, 실제 플레이 확인 필요)

- **서풍 연(Zephyr Kite) Standard 6%**: 지역 4에서 장기전 누적 피해로 무너짐. 오토플레이어가 편대를 전투당 1회만 띄워 항모형의 강점을 못 살리는 한계와 겹침. 사람이 편대를 적극 운용할 때의 승률을 먼저 측정하고, 그래도 낮으면 선체·장갑 상향.
- **Standard 39% / Story 66% / Harsh 19%** (승무원 성장·항구 영입 반영 후, 여명의 피난처): 세 난이도 모두 목표 범위 안. 성장 효과와 영입 비용이 장비 구매와 경쟁하므로 실제 플레이에서 선택 체감 확인. 지역 4~6 화력 배율(현재 1.28/1.5/1.7)과 난이도 화력 배율(0.66/1.0/1.2)이 조정 지점.
- **신중 전략(편대·과부하 미사용) 0~3%**: 공습·강습에 요격·호위로 대응하지 않으면 이길 수 없는 구조. 튜토리얼 힌트로 충분한지 실제 플레이로 확인.
- **감시함 대 순양함 격차**: 천공문 기준 감시함이 순양함보다 쉬움(로스터 개성인지 결함인지 미결).
- **강제 배치 감사(`--enemy=`)는 절대 척도가 아님**: 무기 체계 도입 이후 순양함도 3%. 상대 비교용으로만 사용.

## 3. 오토플레이어(헤드리스 감사) 개선

- 편대를 준비될 때마다 재출격시키면 손실·군수품 소모로 오히려 승률 하락(15%). "전력이 온전할 때만 재출격" 같은 중간 규칙 실험 필요.
- 침입자 대응(해병 이동) 없음 → 강습 바지선 계열이 과소평가됨.
- 전력 배분은 여분을 무장실에만 넣음. 상황별(결계·엔진) 배분 없음.
- 항구 구매 우선순위가 고정 목록. 기함별 우선순위 필요(서풍은 갑판·편대 모듈).

## 4. UI/UX 다듬기

- 전투 명령 패널의 무기 슬롯은 3줄까지만 표시(철벽 하드포인트 3개는 맞지만 모듈로 늘리면 넘침).
- 항구 화면의 장비 시장과 승무원 명단을 탭으로 분리함. 장비 시장 내부의 모듈 3·무기 2·편대 1 카드 밀도는 실제 플레이에서 추가 확인.
- 튜토리얼 힌트가 전투 4단계만 다룸. 항구·무기 슬롯·편대 격납고 안내 없음.
- 피날레 승리 화면 문구가 일반 승리와 동일(`ui.victory_body`). 천공문 수호함 격파 전용 문구 필요.
- 영어 UI에서 긴 문자열(모듈·무기 설명, 이벤트 선택지) 줄바꿈 QA 안 함.
- 고대비·움직임 감소 옵션은 평면도·루트 지도에 반영됐지만 항구·이벤트 화면은 미반영.
- 루트 지도 노드 아이콘 글리프(▲+◆$▼◇★)가 폰트에 따라 깨질 수 있음(현재 macOS 기본 폰트에서만 확인).

## 5. 기술 부채

- `run_headless_audit.sh`가 이제 `Core/*.cs`·`Content/*.cs`를 글롭하므로(`dc11a45`) 새 Core 파일은 자동 포함되지만, 외부 dotnet 하네스(`scratchpad`)는 세션별 임시물이라 저장소에 없음. `tools/`에 dotnet 테스트·감사 프로젝트를 체크인하면 Mono 없이도 CI에서 돌릴 수 있음.

- `GameView.cs`(~1,100줄)와 `GameSimulation.cs`(~1,300줄)가 큼. 화면별·규칙군별 파일 분리 권장(`ShipBlueprintView`처럼).
- EditMode 테스트가 `GameSimulationTests.cs` 한 파일(109개). 콘텐츠·전투·캠페인·저장으로 분리.
- PlayMode 테스트 6개. 기본 전투 명령·항구 영입·배경 전환·선체/구획 확대 및 실제 UI 레이캐스트 검사 포함. 편대 교체 흐름은 추가 필요.
- 세이브 픽스처는 v1만 존재. 스키마 버전을 올릴 때 `Aether Ark → Write Save Fixtures`로 새 폴더 생성 규칙 유지.
- 생성 스크립트 4종(`gen_events/modules/weapons/wings/enemies.py`)은 수동 실행. 검증기(`validate_project.py`)에 "생성 결과가 최신인지" 검사 추가 권장.
- Unity 6000.6.0f1로 에디터가 프로젝트를 자동 업그레이드함(README는 Unity 6 LTS 명시). 팀 표준 버전 확정 필요.
- 첫 원정 고정 시드는 여전히 승리하지만, 무기·모듈 도입으로 원래 "감사된 첫 원정"의 내용은 크게 달라짐. 튜토리얼 흐름을 한 번 손으로 플레이해 확인 필요.

## 7. 참고: 디버그 진입 플래그

개발 빌드에서 `Builds/AetherArk.app`에 인자로 전달합니다.

| 플래그 | 동작 |
|---|---|
| `-debug-combat <구성 id>` | 해당 적과의 전투(예: `cruiser`, `gate_warden`). `-debug-unpaused`, `-debug-damage` 조합 가능 |
| `-debug-route [n]` | n회 도약 후 루트 지도 |
| `-debug-event <id>` | 특정 이벤트 화면 |
| `-debug-port` | 첫 천공문 통과 후 항구 |
| `-debug-setup` | 원정 준비 화면 |
| `-debug-flagship <id>` | 개발용 기함 지정: `ship_vanguard`, `ship_bastion`, `ship_zephyr` |
| `-debug-english`, `-debug-high-contrast` | 영어 및 고대비 화면 검수 |

헤드리스 감사: `dotnet` 하네스 또는 `bash tools/run_headless_audit.sh`. 옵션 `--report`, `--strategy=cautious`, `--flagship=<id>`, `--enemy=<id>`.
