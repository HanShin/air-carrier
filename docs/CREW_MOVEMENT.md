# 선원 이동·작업 동작 개선

기준일: 2026-09-05. 즉시 구획 변경과 원형 토큰을 실제 이동 시간·출입구 경로·관절형 2D 선원 표현으로 교체했습니다. 함선 수치 상향 없이 **이동과 도착 시점이라는 전투 규칙을 변경**한 작업입니다.

## 조작과 동작

- 선원 초상 또는 갑판 캐릭터 선택 → 목적지 구획 클릭. 선택하면 갑판이 확대되고, 남은 경로는 청록색 선·목적지는 황동색 십자로 표시됩니다. 같은 선원을 다시 누르면 선택 해제됩니다.
- 일시정지 중에는 명령만 예약됩니다. 재개해야 실제로 걷습니다. 개발용 격리 전투에서는 F8 한 번에 0.1초씩 확인할 수 있습니다.
- 같은 목적지를 반복해서 클릭해도 출발 위치·속도·경로를 초기화하지 않습니다. 이동 중 다른 목적지를 지정하면 현재 위치에서 경로를 다시 계산합니다.
- 방끼리 공유하는 벽의 중앙에 출입구를 배치합니다. 모서리만 닿거나 떨어진 방은 연결하지 않습니다. 세 기함 각각의 모든 구획 쌍을 테스트합니다. 경로는 출입구 개수를 기준으로 탐색하며, 방 내부는 직선으로 이동합니다.
- 출발 가속·도착 감속·방향 전환과 번갈아 움직이는 팔·다리를 표현합니다. 종족별 체형·귀·깃털·색상 차이, 함장/선택 링, 수리 도구·불꽃, 소화기 분사, 조작 동작, 쓰러진 자세를 구분합니다. 런타임 벡터 메시이므로 새 외부 이미지·모델·플러그인은 사용하지 않습니다.
- 위치와 동작 시간은 시뮬레이션에서 읽습니다. UI 전체가 다시 그려져도 걷기 단계가 초기화되지 않으며, 실제 전투 틱마다 위치를 갱신합니다. 일시정지·F9 정지 중에는 동작도 멈춥니다. 움직임 감소는 보행 과장·손동작·불꽃을 억제하지만 이동 시간을 없애지는 않습니다.

## 전투 규칙

| 항목 | 적용 |
|---|---|
| 이동 속도 | 갑판 셀/초: 인간·엘프 1.5, 드워프 1.05, 오크 1.25, 고블린 1.8, 조인 1.65 |
| 부상 | 체력 40% 미만이면 속도 60% |
| 이동 중 | 수리·소화·파공 봉합·백병전 방어·배치 숙련 보너스·공명 과부하·의무실 치료/보조 효과 중단 |
| 구획 위험 | 출입구 통과 시 실제 `currentRoom` 변경. 그 구획의 화재·산소 부족·침입자 피해 적용 |
| 도착 후 | 구획 작업·치료·배치 효과 재개. 작업 애니메이션은 현재 구획의 우선 위험을 나타냄 |
| 조종사 | 이동 중 출격은 비용/RNG 변경 없이 안내 후 거절. 도착하면 기존 출격 조건 사용 |
| 구조 대기·사망·출격 중 | 이동 명령 거절. 이동 중 쓰러지면 그 위치에서 정지. 쓰러진 선원을 클릭해 옮기던 즉시 이동도 차단 |
| 전투 종료 | 승리 후 비전투 정비 시간에 활동 가능한 선원의 남은 이동을 완료. 쓰러진 선원은 옮기지 않음 |

도착·피해·작업 판정 정밀도는 기존 전투 틱(최대 0.1초)과 같습니다. 수리·소화·봉합의 기존 동시 처리량은 유지하고, 이동 중 적용만 중단했습니다. 모든 조종사에게 비행갑판까지 걷게 하는 별도 탑승 절차는 이번에 추가하지 않았습니다.

## 저장·결정론

- 프로필 v2 유지, **런 v2**. `CrewMovementState`에 갑판 좌표·방향·속도·누적 보행 거리·목적지·남은 waypoint를 저장합니다.
- 런 v1은 기존 구획을 보존해 정지 위치로 이관합니다. Unity가 누락 필드를 0값 객체로 복원하더라도 v1에서는 이동 필드를 읽지 않습니다.
- 스냅샷 봉투 형식은 v1 유지. 런 v1 캡처도 읽을 수 있지만 이동 규칙 변경 안내가 표시되며, 원본 파일은 변경하지 않습니다. 다른 빌드나 이전 규칙의 전투 결과까지 동일하다고 보장하지 않습니다.
- 새 스냅샷은 구획 밖 좌표·벽을 가로지르는 경로·불가능한 이동 상태를 거절합니다. 같은 빌드·캡처·명령·고정 스텝의 재현성을 테스트합니다.
- 기존 `Fixtures/v1`, `Fixtures/v2`는 보존했습니다. 새 `Fixtures/v3`는 프로필 v2·런 v2의 이동 중 전투와 전용 스냅샷입니다. `FixtureWriter`는 새 폴더에 한 번만 쓰며 기존 파일이 있으면 보존합니다.

## 검증

- Unity 자동 테스트 **267/267 통과**: EditMode 235개(기존 216 + 이동 19), PlayMode 32개(기존 28 + 이동 UI 4). 전체 런타임 C# 스모크와 프로젝트 정적 검증도 통과했습니다.
- **macOS 개발 빌드·실행 검수 완료.** v3 이동 스냅샷을 열어 확대 갑판·고대비 선원·수리/소화/쓰러짐 표시를 확인했습니다. F8로 0.3→0.4초 위치 갱신, 실시간 재개 후 기관사의 무장실 도착·작업, 일시정지와 0.3초 스냅샷 재복원을 확인했습니다. 에디터에서 만든 픽스처의 다른 빌드 경고도 표시됐습니다.
- 이동 목적지의 누락 번역 키 표시를 수정하고 양 언어 회귀 검사를 추가했습니다. 최종 macOS 재빌드에서도 `HP … → Weapons` 표시를 확인했습니다.
- 검수 전후 일반 프로필·백업 및 커밋 대상 스냅샷 원본의 SHA-256이 같았습니다. 실행 로그에 오류·예외가 없었습니다. 네이티브 마우스 자동 입력은 선택을 확정하지 못했으므로, 버튼 선택·경로 표시·양 언어 클릭 판정의 근거는 PlayMode 테스트입니다. Windows 실행과 대표 사양 60fps 측정은 아직 하지 않았습니다.
- EditMode: 구획 연결 3기함×100쌍, 이동/재지정/가감속/부상/위험/배치 효과/출격 차단, 이전 저장 이관, 이동 중 저장·스냅샷 재현, 잘못된 경로 거절.
- PlayMode: 실제 선택·목적지 버튼, 선택 경로, F8 위치 갱신, 일시정지·UI 재생성·움직임 감소, 8명 표시와 양 언어 클릭 판정, 작업·쓰러짐 상태.
- 튜토리얼 시드 32838은 자동 완주 유지.

동일한 첫 100개 시드(`17000 + i × 7919`), Standard, `adaptive` 정책으로 300회 점검했습니다. 아래 이전 수치는 `WING_POLICY_AUDIT.md`의 이동 도입 전 기록입니다.

| 기함 | 이전 완주 | 이동 도입 후 |
|---|---:|---:|
| 여명의 피난처 | 48/100 | 47/100 |
| 철벽 | 50/100 | 50/100 |
| 서풍 연 | 17/100 | 13/100 |

```sh
bash tools/run_headless_audit.sh --tutorial
bash tools/run_headless_audit.sh 100 Standard 17000 --flagship=ship_vanguard --wings=adaptive
bash tools/run_headless_audit.sh 100 Standard 17000 --flagship=ship_bastion --wings=adaptive
bash tools/run_headless_audit.sh 100 Standard 17000 --flagship=ship_zephyr --wings=adaptive --report
```

서풍의 종료 코드 2는 기존 25% 감사 기준 미달이며 실행 오류가 아닙니다. 시간 초과는 없었습니다. 기존 AI는 손상 구획 우선순위를 0.1초마다 재평가하며 이동 시간에 특화된 운용을 하지 않습니다. 실제 사람의 완주율·선호도·60fps 검증이 아니며, 기존 감사 JSON을 새 결과로 덮어쓰지 않았습니다. Story/Harsh 전체 회귀와 별도 시드 검증은 다음 밸런스 작업에 남습니다.

## 남은 범위

- 선원 간 물리 충돌·양보·문 개폐 조작·잠금·위험 자동 우회는 없습니다. 문 표시는 경로와 근접 상태를 알려주는 표현입니다.
- 3D 모델/리깅, 개별 장비별 애니메이션, 실내 소품 충돌, 쓰러진 선원을 운반하는 구조 명령은 별도 작업입니다.
- 작은 구획에 다수가 모이면 외형이 겹칠 수 있으므로 초상 명단으로도 선택할 수 있습니다. 전체 UI의 좁은 화면 반응형 배치는 기존 별도 과제입니다.
- 다음은 실제 수리 도착 시간·기관사 잔류·조종사 이동을 고려한 수동 플레이와 감사 지점 스냅샷 내보내기입니다. 서풍 상향 수치는 이 검증 후 결정합니다.
