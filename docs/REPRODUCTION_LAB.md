# 시드·전투 스냅샷 재현 도구

기준일: 2026-09-05. 개발 빌드/Unity 에디터에 **F9 재현실**을 추가했습니다. 같은 시작 조건 또는 저장한 전투 상태에서 결정을 비교하기 위한 도구이며, 일반 원정·해금·밸런스 수치를 변경하는 기능은 아닙니다.

후속 선원 이동 개선으로 현재 런은 v2이며, 이동 중 좌표·속도·경로도 캡처합니다. 런 v1 스냅샷은 정지 위치로 이관하고 다른 규칙 경고를 표시합니다. 아래 244개 테스트와 전투 규칙 불변 설명은 재현실 최초 구현 시점 기록이며, 최신 이동 규칙·검증은 `CREW_MOVEMENT.md`를 참고하십시오.

후속 **감사 지점 내보내기**도 완료했습니다. `--snapshot-dir/--snapshot-battle/--snapshot-tick`으로 자동 플레이의 실제 후반 상태를 이 재현실에 가져올 수 있습니다. 경계 정의·Mono/Unity 차이·출처 정보·최신 280개 테스트는 `AUDIT_CHECKPOINTS.md`를 참고하십시오.

## 사용법

1. 메뉴·준비·전투 화면의 **재현 [F9]**를 누릅니다. 다른 게임 화면에서도 F9로 열 수 있습니다. 재현실이 열려 있는 동안 전투 시간은 흐르지 않으며 원래 일시정지/경고 상태도 변경하지 않습니다.
2. 시드, 기함, 난이도를 선택하고 **항로 시작** 또는 **초기 전투**를 누릅니다. 인간 `Audit Captain`·공작선·튜토리얼 없는 6공역을 사용합니다. 시드 `32838`도 일반 6공역으로 실행합니다. 접근성·음향 설정은 현재 프로필에서 복사합니다.
3. 전투 중 F9 → **현재 전투 스냅샷 저장**으로 상태를 보관합니다. 일반 원정을 테스트 모드로 바꾸지 않고 읽기 전용으로 캡처하는 것도 가능합니다.
4. 경로 입력칸의 JSON을 **불러오기**로 복원합니다. **최근 스냅샷 경로 선택**은 경로만 채우고, 불러오기를 눌러야 실제로 전환됩니다. 외부에서 받은 전용 스냅샷의 전체 경로도 입력할 수 있습니다.
5. 불러온 전투는 일시정지 상태입니다. 창을 닫아 명령한 뒤 **F8**로 정확히 **0.1초씩** 진행하거나, 일반 일시정지 해제로 플레이합니다. F8은 일시정지된 테스트 전투에서만 작동하며, 재현실 안에서도 사용할 수 있습니다. 같은 단계 진행 버튼도 있습니다.
6. **원래 게임으로 돌아가기**를 누르면 원래 프로필·원정 객체·화면으로 복귀합니다. 확인 창을 닫을 때까지 원래 게임은 계속 멈춰 있으며, 닫으면 원래 일시정지 상태로 이어집니다.

`TEST · Seed …` 표시는 일반 게임이 아닌 격리된 테스트 세션임을 뜻합니다. 재현실과 음향 설정은 동시에 열리지 않으며, 재현실 입력 중 숫자키나 기존 전투 명령이 뒤의 전투로 전달되지 않습니다. 릴리스 빌드에서는 F9/F8/디버그 진입이 비활성화됩니다.

전투 중 재현실을 열면 저장 버튼이 먼저 선택됩니다. **방향키·Enter**로 버튼을 선택·실행할 수 있으며, 전투가 없으면 시드 입력칸에서 시작합니다.

## 저장과 복구 보장

일반 저장 폴더 아래 별도 하위 폴더를 사용합니다.

```text
Application.persistentDataPath/
├─ profile.json                  일반 프로필 — 테스트에서 쓰지 않음
├─ suspended_run.json            일반 원정 — 테스트에서 쓰지 않음
└─ reproduction/
   ├─ session/                   테스트용 profile.json / suspended_run.json
   └─ snapshots/                 날짜·시드·고유 ID별 불변 스냅샷
```

macOS 기본 위치는 `~/Library/Application Support/Aether Ark Studio/Aether Ark Prototype/reproduction/`입니다. Windows는 Unity의 해당 제품 `Application.persistentDataPath` 아래 같은 구조입니다. 프로젝트의 `Assets`나 일반 원정 파일을 스냅샷으로 덮어쓰지 않습니다.

- 테스트 진입은 프로필을 복사하고 저장 대상을 교체합니다. 원래 프로필·원정은 메모리에 보관합니다. 테스트의 자동 저장·새 원정·이어하기·포기·승패 처리는 테스트 저장소에만 적용됩니다. 테스트 승리로 일반 해금을 기록하지 않습니다.
- **기존 모든 `-debug-*` 진입도 이제 같은 격리 저장소를 사용합니다.** 이전 디버그 경로가 일반 원정을 덮어쓸 수 있었던 문제를 함께 차단했습니다.
- 현재 프로세스에서는 원래 게임으로 즉시 돌아갈 수 있습니다. 앱을 종료한 뒤의 일반 이어하기는 기존 자동 저장 시점을 사용합니다. 재현실은 일반 게임을 새로 자동 저장하는 기능이 아니므로, 디스크에 없던 원래 상태를 앱 재시작 후 되살린다고 보장하지 않습니다.
- 테스트가 승리/패배하거나 테스트 원정을 포기해도 캡처 파일은 삭제하지 않습니다. 이전 캡처를 덮어쓰지 않고, 새 파일을 같은 디렉터리의 임시 파일에 기록·flush한 뒤 이동해 공개합니다. 임시 파일은 최근 캡처 검색에 포함하지 않습니다.
- 일반 저장은 현재 프로필 v2·런 v2입니다. 전용 스냅샷 형식은 `aether-ark-combat-snapshot`, 버전 1이며 런 v1/v2를 지원합니다. 일반 `suspended_run.json`을 직접 불러오는 기능은 아닙니다.

## 스냅샷 내용과 한계

전체 `RunState`와 프로필을 JSON payload로 저장합니다. 승무원·편대·부상·구획·장비·자원·고도·기상·선택 표적·전투 타이머·알림·로그·항로와 분리된 route/combat/events RNG 상태가 포함됩니다. UTC 생성 시각, 런타임 어셈블리 빌드 ID(MVID), Unity 버전, SHA-256 검사값도 기록합니다.

저장/파일 읽기는 현재 시뮬레이션이나 RNG를 변경하지 않습니다. 불러오기 UI는 **복원한 사본의 일시정지를 켜며**, 런 v1이면 이동 상태를 이관합니다. 원본 파일은 변경하지 않으며 지난 전투 로그의 효과음도 재생하지 않습니다. 다른 빌드/Unity 버전/이전 이동 규칙은 경고를 표시하며 이후 결과가 같다고 보장하지 않습니다. 지원하지 않는 형식·런·프로필 버전은 거절합니다.

누락 파일, 잘못된 JSON·검사값, 필수 상태 누락, 잘못된 구획/임무/무장, 초기화되지 않은 RNG, 비정상 숫자, 8MiB 초과 파일은 안내와 함께 거절합니다. 유효성 확인 및 테스트 저장 준비가 끝나기 전에는 현재 게임을 교체하지 않습니다. SHA-256은 손상 검출용이며, 발신자 인증이나 악의적인 편집의 방지를 뜻하지 않습니다.

**시드만 같다고 후반 전투가 재현되는 것은 아닙니다.** 항로 선택·사건 결과·항구 구매·장비·승무원·이전 피해·명령 시점이 누적됩니다. 초기 전투 버튼은 새 원정의 자연 생성 1티어 전투이며, 감사 도구가 여러 지역을 지나 도달한 전투가 아닙니다. 후반 전투 비교는 그 지점의 스냅샷을 사용해야 합니다.

같은 빌드·스냅샷·명령 순서·0.1초 단계에서는 결정론적 상태 비교가 가능합니다. 일반 실시간 플레이는 프레임 간격에 영향을 받으므로 이 기능을 명령 자동 기록/재생이나 영상 리플레이로 해석하지 않습니다. 음향·UI의 표시 시간은 전투 RNG와 별개입니다.

## 명령줄 진입

macOS 개발 빌드 예시:

```sh
open -na Builds/AetherArk.app --args -debug-repro
open -na Builds/AetherArk.app --args -debug-seed 17000 -debug-flagship ship_zephyr -debug-difficulty Standard
open -na Builds/AetherArk.app --args -debug-seed 17000 -debug-battle -debug-flagship ship_zephyr -debug-difficulty Standard
open -na Builds/AetherArk.app --args -debug-snapshot "/absolute/path/to/capture.json"
```

Windows 개발 실행 파일에도 동일한 인자를 전달할 수 있습니다(실제 Windows 실행은 미검증).

- `-debug-seed <정수>`: 정확한 signed 32-bit 시드. 실패 시 임의 시드로 대체하지 않음.
- `-debug-battle`: `-debug-seed`와 조합해 초기 전투로 바로 진입. 생략하면 항로.
- `-debug-difficulty Story|Standard|Harsh`: 시드 진입에만 적용, 기본 Standard.
- `-debug-flagship <id>`: 시드 또는 기존 디버그 기함 지정. 시드 재현의 기본은 `ship_zephyr`.
- `-debug-snapshot <전체 경로>`: 전용 스냅샷을 검사하고 일시정지 상태로 복원.
- `-debug-repro`: 재현실 화면으로 바로 진입.
- `-debug-english`, `-debug-high-contrast`: 시각 검수 설정.

시드·스냅샷을 동시에 지정하거나, 새 진입과 `-debug-combat/-debug-route/-debug-event/-debug-port/-debug-setup/-debug-damage/-debug-pilots/-debug-unpaused`를 섞으면 오류로 안내합니다. 스냅샷에는 기함·난이도가 들어 있으므로 기함/난이도 재지정과도 섞지 않습니다. 기존 `-debug-combat <적>`의 적을 찾는 시드 검색은 유지하되 새 시드 진입에서는 사용하지 않습니다.

## 검증과 다음 작업

- EditMode **216/216 통과**: 기존 179개 + 재현 저장소/시드/무결성/결정론 검사 37개.
- PlayMode **28/28 통과**: 기존 19개 + 재현실/격리/복원/오류/명령줄/클릭 검사 9개.
- 일반 프로필·런·백업 파일의 전후 바이트와 메모리 상태를 비교합니다. 출격 중 스냅샷, 경고·손상 상태, 150회 동일 명령/고정 스텝, 종료 상태에서 캡처 보존, 테스트 이어하기, 잘못된 입력과 양 언어 안내를 포함합니다.
- C# 컴파일 스모크·프로젝트 정적 검증과 **macOS 개발 빌드 통과**. 실제 Windows 빌드/실행 및 플랫폼 간 동일 결과 검증은 아직 하지 않았습니다.
- macOS 실행 앱에서 서풍·표준·시드 17000의 초기 전투를 열고, 한국어 재현실에서 키보드로 캡처 → F8 0.1초 진행 → 0.0초 복원을 확인했습니다. 앱 종료 후 같은 파일을 `-debug-snapshot -debug-english -debug-high-contrast`로 다시 불러와 영어 안내와 일시정지 HUD도 확인했습니다. 두 실행 로그에 오류/예외가 없었습니다.
- 이 실행 검수 전후 일반 `profile.json`과 `.bak`의 SHA-256이 동일했고, 없던 일반 `suspended_run.json`도 생성되지 않았습니다. 재시작 복원 전후 스냅샷 파일의 해시도 동일했습니다. 실제 마우스 조작은 별도 확정하지 않았으며 버튼 raycast/콜백은 PlayMode로 검증했습니다.
- 전투 규칙·장비 수치는 바꾸지 않았으며 기존 캠페인 감사 JSON도 보존했습니다. 사람의 완주율·플레이 시간·밸런스 검증을 완료했다는 의미는 아닙니다.

**헤드리스 감사 지점 내보내기 연결은 후속 완료**했습니다(`AUDIT_CHECKPOINTS.md`). 다음은 서풍의 손실 사례에서 같은 시작 상태를 불러와 기관사 잔류/정찰 유지/요격 예약을 수동 A/B로 비교해 기록하는 것입니다. 이후에도 손실 원인이 반복될 때에만 전력·군수품·내구도 중 한 축씩 조정합니다.
